# SRT 字幕时间校正工具

供纪录片剪辑师使用的网页工具：粘贴或上传 SRT 字幕，录入若干“原片时间 → 成片时间”锚点，工具对每条字幕的起止时间做**分段线性映射**，输出校正后的 SRT；并可将校正后的主轨与成片时间轴上的副轨 SRT 做**双语字幕对齐**，导出对照 CSV；还能把主轨上时间相互重叠的字幕做**重叠字幕分轨**（最多 4 轨，可逐条锁定轨号），各轨单独下载 SRT。

## 功能

- 粘贴 SRT 文本或上传 `.srt` 文件
- 至少录入两个锚点；**原片时间、成片时间两组均须严格递增**，否则明确报错
- 相邻锚点之间线性插值；锚点范围之外沿用最近锚点的固定偏移；结果按毫秒取整
- 保留原序号与多行正文
- 页面展示每条字幕“原时间 / 新时间”对照表
- 若映射后出现**起止倒置**或**字幕顺序倒置**，阻止导出并逐条指出问题
- 一键下载校正后的 SRT
- 双语字幕对齐：以校正后的主轨对副轨 SRT 做**保持顺序的一对一配对**（仅时间区间交叠 > 0 才可配对，允许跳过无对应字幕）
- 页面展示配对结果及两侧未配对条目，并可下载含双方序号、时间、正文的 CSV
- 副轨 SRT 无效时给出解析错误，不影响主轨 SRT 的导出
- 重叠字幕分轨：直接使用最近一次校正成功的主轨 SRT，每次处理 **1～24 条**，任意条目可锁定到 **1～4 号轨**，其余自动分配
- 全部字幕必须且只能出现一次；同轨字幕的**左闭右开**时间区间不得有正长度交叠（端点相接可共轨）；锁定轨号不改变
- 全局求解：先**最小化最大轨号**，再在其中取**按原文件位置排列的轨号向量字典序最小**者（不做逐条贪心，不会把全局可解的方案误报为无解）
- 页面展示每条字幕的原位置、时间、锁定值与最终轨号；各非空轨可单独下载 SRT（轨内按起点、原位置排序并从 1 编号，时间与多行正文不变）
- 条数超限、锁定值非法、时长非正、同轨锁定冲突或四轨内无解时给出定位错误，**不生成任何部分下载**
- 主轨或锁定值改变后，旧分轨结果自动失效；原校正与双语对齐功能照常使用

## 快速开始（Docker）

一条命令启动：

```bash
docker compose up --build
```

然后在浏览器访问：

```
http://localhost:3000
```

- Web 地址：`http://localhost:3000`
- API 基址：`http://localhost:3000/api`（端点：`/api/convert`、`/api/align`、`/api/split-tracks`）
- 端口：`3000`（宿主机 `3000` → 容器 `3000`，见 `compose.yaml`；可在 `compose.yaml` 的 `ports` 改为如 `"8080:3000"`）
- 如需改容器监听端口，设置环境变量 `PORT`（例如 `PORT=8080`，并相应映射端口）

镜像构建时会自动执行 `npm ci --omit=dev` 安装依赖，无需本地安装 Node.js。

## 使用说明

1. 在文本框粘贴 SRT 内容，或点击“选择文件”上传 `.srt`。
2. 添加至少两个锚点，格式为 `HH:MM:SS,mmm`（例如 `00:01:23,456`）：
   - **原片时间**：字幕当前（错误）的时间轴上的参考点
   - **成片时间**：该参考点在成片时间轴上的正确位置
3. 点击“开始校正”，页面显示原时间与新时间对照表。
4. 无错误时点击“下载校正后的 SRT”导出结果。
5. 校正成功后，在第 4 步粘贴或上传**成片时间轴上的副轨 SRT**（另一语言），点击“开始对齐”：
   - 页面列出配对结果（含每对交叠毫秒数）与主轨、副轨两侧的未配对条目；
   - 点击“下载对齐 CSV”导出对照表；
   - 副轨解析失败时仅提示错误，主轨 SRT 的导出不受影响。
6. 校正成功后，在第 5 步“重叠字幕分轨”中对主轨逐行设置锁定（不锁定则自动分配），点击“开始分轨”：
   - 页面列出每条字幕的原位置、起止时间、锁定值与最终轨号；
   - 每个非空轨出现一个下载按钮，导出该轨 SRT；
   - 条数超过 24、锁定值非法、时长非正或四轨内无解时只提示错误，不会生成下载；
   - 修改任何锁定值或重新校正后，旧分轨结果立即失效，需要重新分轨。

## 映射规则

设锚点为 `(s₁→d₁), (s₂→d₂), …, (sₙ→dₙ)`（`s`、`d` 各自严格递增），对任意时间 `t`：

- `t ≤ s₁`：`t' = t + (d₁ − s₁)`（沿用首锚点固定偏移）
- `t ≥ sₙ`：`t' = t + (dₙ − sₙ)`（沿用末锚点固定偏移）
- `sᵢ ≤ t ≤ sᵢ₊₁`：线性插值 `t' = dᵢ + (t − sᵢ) · (dᵢ₊₁ − dᵢ) / (sᵢ₊₁ − sᵢ)`

每条字幕的开始、结束时间分别独立映射，结果四舍五入到毫秒。

## 对齐规则

主轨为 `/api/convert` 成功返回的校正后 SRT，副轨为成片时间轴上的另一语言 SRT，两轨均按文件顺序参与配对：

- 仅当两条字幕的**时间区间交叠 > 0** 时才允许配对；配对为**一对一**且不得交叉（保持两轨顺序）；
- 用动态规划求使**配对交叠毫秒数总和最大**的方案；
- 平分时取**配对起点差 |主轨开始 − 副轨开始| 总和较小**的方案；
- 仍平分时**按序号靠前**确定结果：优先配对当前条目，其次跳过副轨条目，最后跳过主轨条目；
- 允许跳过无对应字幕的条目，未配对条目在页面与 CSV 中单独列出。

CSV 列为：`状态, 主轨序号, 主轨开始, 主轨结束, 主轨正文, 副轨序号, 副轨开始, 副轨结束, 副轨正文, 交叠毫秒`。先列出全部配对行，再依次列出主轨、副轨未配对行；文件带 BOM，可直接用 Excel 打开。

## 分轨规则

输入为 `/api/convert` 最近一次成功返回的主轨 SRT，每次处理 1～24 条字幕：

- 每条字幕必须且只能分配到一条轨；轨号为 1～4 的整数；
- 同轨任意两条字幕的**左闭右开**时间区间 `[开始, 结束)` 不得有正长度交叠；**端点相接**（一条的结束 = 另一条的开始）可共轨；
- 用户可把任意条目**锁定**到 1～4 号轨，求解时锁定轨号不得改变；未锁定条目自动分配；
- 时长非正（结束 ≤ 开始）的条目在分轨前逐条报错；
- 优化目标按优先级：
  1. **最小化最大轨号**（即使用的轨数）；
  2. 在所有达到最小轨数的方案中，取**按原文件位置排列的轨号向量字典序最小**者（位置靠前的条目优先取小轨号）。
- 求解为**全局精确求解**：按起点排序做“各轨最后结束时间”状态 DP 判定可行性，再按文件位置逐条用可行性判定收缩出字典序最小解；不是逐条贪心，因此不会把全局可解的实例误报为无解；
- 输出轨内按（开始时间、原位置）排序并从 1 重新编号，**时间与多行正文保持不变**；仅非空轨生成 SRT；
- 四轨内不存在可行方案时返回“无可行分轨”（附交叠深度等说明），不生成任何部分下载。


## API

`POST /api/convert`

```json
{
  "srt": "1\n00:00:01,000 --> 00:00:03,000\n字幕\n",
  "anchors": [
    { "src": "00:00:01,000", "dst": "00:00:02,000" },
    { "src": "00:00:12,000", "dst": "00:00:15,000" }
  ]
}
```

返回每条字幕的对照信息；无错误时附带 `srt` 字段（校正后的完整文本），存在倒置问题时 `errors` 非空且不返回 `srt`。

`POST /api/align`

```json
{
  "primary": "1\n00:00:02,000 --> 00:00:04,000\n你好\n",
  "secondary": "1\n00:00:02,500 --> 00:00:03,500\nHello\n"
}
```

- `primary`：主轨 SRT 文本（通常取 `/api/convert` 成功返回的 `srt` 字段）
- `secondary`：副轨 SRT 文本（成片时间轴）

成功时返回 `pairs`（含双方序号、时间、正文与交叠毫秒）、`unmatchedPrimary` / `unmatchedSecondary`、`stats` 与 `csv` 字段；主轨 / 副轨解析失败分别返回 `primaryParseErrors` / `secondaryParseErrors`（HTTP 400），条目数量超出对齐上限时返回 `alignErrors`（HTTP 400）。

`POST /api/split-tracks`

```json
{
  "srt": "1\n00:00:02,000 --> 00:00:04,955\n第一行字幕\n\n2\n00:00:03,182 --> 00:00:05,545\n重叠的第二段\n",
  "locks": [{ "position": 1, "track": 3 }]
}
```

- `srt`：主轨 SRT 文本（通常取 `/api/convert` 成功返回的 `srt` 字段），每次 1～24 条
- `locks`：可选，锁定数组；`position` 为字幕在主轨中的位置（从 1 开始），`track` 为 1～4 的整数轨号

成功时返回：

- `stats`：`{ entries, tracks, locked }`（总条数、使用轨数、锁定条数）
- `entries`：按原位置排列，每项含 `position`、`index`、`start`、`end`、`text`、`locked`（未锁定为 `null`）、`track`（最终轨号）
- `tracks`：仅含非空轨，每项含 `track`、`count`、`srt`（轨内按起点、原位置排序并从 1 编号，时间与正文不变）

失败时（均为 HTTP 400，不生成任何下载）：

- `parseErrors`：SRT 为空或解析失败
- `splitErrors`：条数超出 1～24、锁定值非法（逐项定位 `locks[i]`）、时长非正（逐条定位）、同轨锁定冲突，或四轨内无可行分轨
