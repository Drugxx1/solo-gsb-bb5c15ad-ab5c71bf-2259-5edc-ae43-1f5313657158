# SRT 字幕时间校正工具

供纪录片剪辑师使用的网页工具：粘贴或上传 SRT 字幕，录入若干“原片时间 → 成片时间”锚点，工具对每条字幕的起止时间做**分段线性映射**，输出校正后的 SRT；可将校正后的主轨与成片时间轴上的副轨 SRT 做**双语字幕对齐**，导出对照 CSV；还可把校正后主轨中**时间上相互重叠的字幕分到多条轨**，逐轨导出 SRT。

## 功能

- 粘贴 SRT 文本或上传 `.srt` 文件
- 至少录入两个锚点；**原片时间、成片时间两组均须严格递增**，否则明确报错
- 相邻锚点之间线性插值；锚点范围之外沿用最近锚点的固定偏移；结果按毫秒取整
- 保留原序号与多行正文
- 页面展示每条字幕“原时间 / 新时间”对照表
- 若映射后出现**起止倒置**或**字幕顺序倒置**，阻止导出并逐条指出问题
- 一键下载校正后的 SRT
- 双语字幕对齐：以校正后的主轨对副轨 SRT 做**保持顺序的一对一配对**（仅时间区间交叠 > 0 才可配对，允许跳过无对应字幕）
- 页面展示配对结果及两侧未配对条目，并可下载含双方序号、时间、正文的 CSV
- 副轨 SRT 无效时给出解析错误，不影响主轨 SRT 的导出
- 重叠字幕分轨：把校正后主轨中时间相互重叠的字幕分配到 **1～4 号轨**（每次 1～24 条），可将任意条**锁定**到固定轨号，其余自动分配；**全局求解**（先最小化最大轨号，再取轨号向量字典序最小者），四轨内无解时明确说明
- 页面展示每条字幕的原位置、时间、锁定值与最终轨号，各非空轨可单独下载 SRT（轨内按起点、原位置排序并从 1 编号，时间与多行正文保持不变）

## 使用说明

1. 在文本框粘贴 SRT 内容，或点击“选择文件”上传 `.srt`。
2. 添加至少两个锚点，格式为 `HH:MM:SS,mmm`（例如 `00:01:23,456`）：
   - **原片时间**：字幕当前（错误）的时间轴上的参考点
   - **成片时间**：该参考点在成片时间轴上的正确位置
3. 点击“开始校正”，页面显示原时间与新时间对照表。
4. 无错误时点击“下载校正后的 SRT”导出结果。
5. 校正成功后，在第 4 步粘贴或上传**成片时间轴上的副轨 SRT**（另一语言），点击“开始对齐”：
   - 页面列出配对结果（含每对交叠毫秒数）与主轨、副轨两侧的未配对条目；
   - 点击“下载对齐 CSV”导出对照表；
   - 副轨解析失败时仅提示错误，主轨 SRT 的导出不受影响。
6. 校正成功后，第 5 步自动列出主轨字幕清单（位置 / 序号 / 时间 / 锁定 / 轨号 / 正文）：
   - 需要固定轨道的字幕，在“锁定”列选择 1～4 号轨，其余保持“自动”；
   - 点击“开始分轨”，页面给出每条字幕的最终轨号，并为每条非空轨提供单独的 SRT 下载；
   - 重新校正、清空主轨或改动任一锁定值后，旧分轨结果自动失效，需重新分轨。

## 映射规则

设锚点为 `(s₁→d₁), (s₂→d₂), …, (sₙ→dₙ)`（`s`、`d` 各自严格递增），对任意时间 `t`：

- `t ≤ s₁`：`t' = t + (d₁ − s₁)`（沿用首锚点固定偏移）
- `t ≥ sₙ`：`t' = t + (dₙ − sₙ)`（沿用末锚点固定偏移）
- `sᵢ ≤ t ≤ sᵢ₊₁`：线性插值 `t' = dᵢ + (t − sᵢ) · (dᵢ₊₁ − dᵢ) / (sᵢ₊₁ − sᵢ)`

每条字幕的开始、结束时间分别独立映射，结果四舍五入到毫秒。

## 对齐规则

主轨为 `/api/convert` 成功返回的校正后 SRT，副轨为成片时间轴上的另一语言 SRT，两轨均按文件顺序参与配对：

- 仅当两条字幕的**时间区间交叠 > 0** 时才允许配对；配对为**一对一**且不得交叉（保持两轨顺序）；
- 用动态规划求使**配对交叠毫秒数总和最大**的方案；
- 平分时取**配对起点差 |主轨开始 − 副轨开始| 总和较小**的方案；
- 仍平分时**按序号靠前**确定结果：优先配对当前条目，其次跳过副轨条目，最后跳过主轨条目；
- 允许跳过无对应字幕的条目，未配对条目在页面与 CSV 中单独列出。

CSV 列为：`状态, 主轨序号, 主轨开始, 主轨结束, 主轨正文, 副轨序号, 副轨开始, 副轨结束, 副轨正文, 交叠毫秒`。先列出全部配对行，再依次列出主轨、副轨未配对行；文件带 BOM，可直接用 Excel 打开。

## 分轨规则

主轨为 `/api/convert` 成功返回的校正后 SRT，每次处理 **1～24 条**字幕，目标是把它们分配到 **1～4 号轨**：

- 每条字幕**必须且只能**出现在一条轨上；
- 同轨字幕的**左闭右开**时间区间 `[开始, 结束)` 不得有正长度交叠；**端点相接**（一条的结束 = 另一条的开始）可共轨；
- 可将任意条**锁定**到 1～4 号轨，锁定轨号不得改变，其余自动分配；
- 优化目标：先**最小化最大轨号**，再取**按原文件位置排列的轨号向量字典序最小**者；求解为带前向检查的全局回溯搜索，**不是逐条贪心**（贪心会把本可 2 轨完成的输入开到 3 轨）；
- 字幕**时长非正**（结束 ≤ 开始）、条数超出 1～24、锁定值非法（非 1～4 整数）时**逐条定位**错误；四轨内无解时说明**无可行分轨**（含同时交叠超限、锁定冲突等原因）；以上情况均不生成任何分轨下载；
- 各非空轨可单独下载 SRT：轨内按（起点、原位置）排序并**从 1 重新编号**，时间与多行正文保持不变；
- 主轨（重新校正 / 清空）或任一锁定值改变后，旧分轨结果自动失效。

```
├── Dockerfile
└── compose.yaml
```

## API

`POST /api/convert`

```json
{
  "srt": "1\n00:00:01,000 --> 00:00:03,000\n字幕\n",
  "anchors": [
    { "src": "00:00:01,000", "dst": "00:00:02,000" },
    { "src": "00:00:12,000", "dst": "00:00:15,000" }
  ]
}
```

返回每条字幕的对照信息；无错误时附带 `srt` 字段（校正后的完整文本），存在倒置问题时 `errors` 非空且不返回 `srt`。

`POST /api/align`

```json
{
  "primary": "1\n00:00:02,000 --> 00:00:04,000\n你好\n",
  "secondary": "1\n00:00:02,500 --> 00:00:03,500\nHello\n"
}
```

- `primary`：主轨 SRT 文本（通常取 `/api/convert` 成功返回的 `srt` 字段）
- `secondary`：副轨 SRT 文本（成片时间轴）

成功时返回 `pairs`（含双方序号、时间、正文与交叠毫秒）、`unmatchedPrimary` / `unmatchedSecondary`、`stats` 与 `csv` 字段；主轨 / 副轨解析失败分别返回 `primaryParseErrors` / `secondaryParseErrors`（HTTP 400），条目数量超出对齐上限时返回 `alignErrors`（HTTP 400）。

`POST /api/split-tracks`

```json
{
  "srt": "1\n00:00:01,000 --> 00:00:04,000\n甲\n\n2\n00:00:02,000 --> 00:00:03,000\n乙\n",
  "locks": [0, 2]
}
```

- `srt`：主轨 SRT 文本（通常取 `/api/convert` 成功返回的 `srt` 字段）
- `locks`：可选，与字幕一一对应的锁定值数组；`0` / `null` 表示自动分配，`1`～`4` 表示锁定到对应轨

成功（HTTP 200）返回：

- `trackCount`：最大轨号（已最小化）
- `entries`：每条字幕的 `pos`（原位置）、`index`（原序号）、`start` / `end`、`text`、`lock`（锁定值）、`track`（最终轨号）
- `tracks`：各非空轨 `{ track, count, srt }`，`srt` 轨内按（起点、原位置）排序并从 1 编号，可直接下载

输入问题（HTTP 400）：`parseErrors`（主轨解析失败）或 `splitErrors`（条数超出 1～24、锁定值非法、时长非正，均逐条定位）。

无可行分轨（HTTP 200）：`{ "ok": false, "infeasible": true, "message": "…" }`，说明原因（同时交叠超过 4 条、锁定冲突等），不返回任何分轨文件。
